# Codex contributor guidance

- Work on a topic branch. Never push to `main`; commit focused changes, open a PR into the agreed integration branch, and wait for review/CI before merging. Do not push or deploy unless requested.
- Layout: `firmware/` is PlatformIO/C++; `cloud/` is the Python API/dashboard; `simulation/` contains JS modules used by the browser, cloud simulator and CI; `scripts/` contains host/measurement tools; `docs/` holds hardware guidance and validation records. Production runs on Render: root `render.yaml` installs `cloud/requirements.txt` and starts `python cloud/server.py`. Groq Whisper (`GroqWhisperASR`, `/api/stt`) handles STT; the WAV CLI uses Groq and Google TTS with standard-library HTTP. Local CPU model experiments and Fly/Docker deployment are retired.
- Use Python 3.11+, Node.js 20+, g++ and PlatformIO Core (CI: 6.2.0). Run `python3 -m unittest discover -s cloud -p 'test_*.py' -v`, `npm test --prefix simulation`, `python3 scripts/run_host_tests.py`, and `python3 -m unittest discover -s scripts -p 'test_*.py' -v` from root.
- Build defaults with `pio run -d firmware`. Also build `mic_test`, `gateway_cloud_compile`, `sensor_node_trace`, `gateway_trace` and `gateway_ai_compile` with `-e`. See `.github/workflows/firmware.yml` for the full verification matrix.
- Pin map: `docs/wiring.md`; confirm actual constants and compile guards in `firmware/src/` and `firmware/include/pump_gpio.h` / `audio_io.h`. Read `firmware/README.md` and `docs/GATEWAY_REFILL_CONTRACT.md` before hardware changes. Keep pump commissioning disabled; do not flash or actuate hardware without explicit authorization.
- Never read, modify, stage or commit `firmware/include/cloud_config.local.h`. Use `cloud_config.local.h.example` for public configuration documentation. Never commit `.env`, tokens, Wi-Fi credentials, database URLs, private recordings or model weights. Do not print secrets in logs.
- Local SQLite uses only the Python standard library. The server reads environment variables directly and automatically applies all numbered SQLite migrations. Postgres schemas are applied explicitly; preserve migration history. Optional Postgres tests require a disposable loopback database, never production.
- Preserve simulation modules, test fixtures and optional tools with documented callers. Before deleting code, trace references through tests, CI, firmware environments and deployment configuration. Historical validation records are evidence for their stated revisions, not current test results.
